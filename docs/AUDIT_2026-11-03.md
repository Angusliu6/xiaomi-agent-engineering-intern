# TRACE-QA v0.2 · 全栈独立审计与第二轮迭代记录

> 审计时间：2026-11-03。范围：GitHub 主干源码、25 项原始测试、CLI、两个数据集、实验与评测协议、PDF 学习手册、PPT 及口试题库、README、CI/安全边界。所有数值只来自本地 CPU 离线测试和自建材料；不代表真实小米业务表现。

## 一页结论（招聘者视角）

**当前是扎实的教学型工程原型，不是已经证实的工业级 Agentic Search 科研成果。** 现在最具辨识度的是：已有企业 LLM Agent 背景，愿意把候选系统写成能跑、能失败、能测试、能推翻自己的工程研究。最明显的短板仍然是：真实模型未接入验证、`hybrid` 是纯词法融合、没有真实人工标注端到端任务、MCP 未在 live client/server 验证。不能用 PPT / README 的完整度替代这些证据。

## 本轮实际做了什么

1. **修复评测对照污染风险**：每次测评产出规范化 benchmark SHA-256 与 corpus SHA-256；`paired_compare` 拒绝不同题库、不同文档内容、不同 gold labels、不同 `k`、重复行与旧版无版本元数据的报告；同时输出逐题 gain/regression IDs。
2. **增强输入正确性**：拒绝空题库、空查询、重复 `gold_docs`、不存在于 corpus 的 gold ID、JSONL 错行，避免把错误标注静默记成模型失败。
3. **改正模型错误分类**：远程 planner 故障变成 `planning_failed` 和可审计 `planner_error`，不再被错误写作 `insufficient_evidence`。检索返回的前 3 条截断片段可进入下一轮规划上下文，明确标记为不可信数据。
4. **收紧外部请求**：仍为显式 opt-in；端点拒绝 URL userinfo/query/fragment、HTTP 重定向，限制响应为 64 KiB，端点响应错误不泄漏 API key。未完成 live 供应商测试，也未建立生产级 SSRF 防护。
5. **增加 19 项审计单测**：原 25 项 + 审计测试 19 项 + CLI 契约测试 7 项，共 51 项通过；包含篡改标签、替换 corpus、重复行、planner 失效、序列化/输入边界、观察片段、URL 等边界。
6. **新增困难压力集**：`data/stress_hard_negative.jsonl` 共 16 道人工合成题（6 可回答、10 高词面重合但没有足够支持的不可回答题）。这是显式的 stress suite，**不是独立自然分布 benchmark**。
7. **修正学习材料**：统一 PPT 的 P0/P1/P2 与路线优先级；添加评测数据防篡改与困难负例两页；更新课件逐页复习题和技术手册审核记录。

## 真实离线结果与严重限制

| 数据集/方法 | 可回答任务 Hit@5 | 不可回答任务正确拒答* | 样本 |
|---|---:|---:|---|
| 原始合成集 B0（BM25） | 19/20 = 95% | 0/3 | 23 |
| 原始合成集 B1（词法 RRF） | 20/20 = 100% | 0/3 | 23 |
| 新困难压力集 B0 | 6/6 = 100% | 0/10 | 16 |
| 新困难压力集 B1 | 6/6 = 100% | 0/10 | 16 |
| 新困难压力集 B2（规则 loop + 弱证据门） | 6/6 = 100% | **4/10 = 40%** | 16 |

\* 这里 B0/B1 的“正确拒答”仅用 `没有检索结果` 作为替代指标；B2 依靠弱词法门。**不是端到端生成模型的 refusal precision / claim-level factual correctness**。旧数据 B0→B1 +1 道的 paired bootstrap 95% 区间为 `[0.00, 0.15]`，包含 0；样本太小，而且数据由作者构造，完全不能推断真实增益。两组数据不能混作一个主测集、不能把 stress 当成真实 holdout。

**最有价值的反例**：`hn003` 询问生产环境真实 P95，文档只介绍 RRF 原理；`hn005` 询问生产故障的精确修复时间，文档只有排障建议。B2 因词汇重合仍把检索文档当作候选证据。这证明目前最大问题不只是“检索是否召回”，而是“材料能否支持问题要求的证据类型”。

## 按严重程度分类的最终缺口

| 严重程度 | 真实问题 | 招聘官可能怎么问 | 下一步可验收产物 |
|---|---|---|---|
| **BLOCKER** | 自建语料无外部效度，原始题过于容易 | “公开真实工程数据也成立吗？” | 明确许可的公开仓库/issue，≥80 条人工校验任务，独立冻结 holdout ≥25 |
| **BLOCKER** | 没有真实 LLM Agent 多轮测试 | “这是规则检索，为什么叫 Agentic？” | 真实模型规划/Tool Call 的 trace，含拒答和错误轨迹；与离线规则策略配对 |
| **BLOCKER** | 无答案/证据蕴含能力弱 | “查到类似文档等于回答了问题吗？” | `claim/evidence` 二级标注、hard negatives、多轮证据门及人工答案评分 |
| **HIGH** | `hybrid` 只有 BM25 + 词法字符 RRF | “Embedding、Reranker 在哪里？” | 真正 Dense / Rerank 配置、同条件消融与成本账单 |
| **HIGH** | MCP 只提供示例 Server，无 live client 测试 | “真正做过 Tool Server 互操作？” | 实际 SDK 测试录像/日志，server/client 互操作与断连失败案例 |
| **HIGH** | checkpoint 只读可重放，不保证写操作 exactly once | “如果执行外部扣费会不会重复？” | 五处 crash injection，工具副作用分级与 idempotency/approval 策略 |
| **HIGH** | LLM 请求可发送文档片段到自选 API 端点 | “能发内部故障日志吗？” | 明确的 PII/保密策略、域名配置/最小化数据、离线安全评估 |
| **MEDIUM** | 没有 P95/并发/成本指标 | “性能工程取舍怎么量化？” | 端到端 P50/P95，tokens/calls，质量-成本 Pareto 曲线 |
| **MEDIUM** | 研究结论可能被自建题偏置 | “标注者是不是知道要优化什么？” | 事先写好的协议、外部审查/盲标、固定 seed 和 holdout |
| **LOW** | PPT 和文档易给人完成度过高错觉 | “这些是已经做成，还是未来规划？” | 每个数据/页面标 `offline prototype` 或 `future / unverified` |

## 下一次真正值得做的实验：Evidence-aware Query Budgeting

**预注册假设**：对多步、需要指定证据类型（负责人、日期、金额、根因）的工程问题，比起按词汇重合就停止，要求 Agent 显式列出“已找到的证据 / 仍缺的证据”，可能提升拒答与带出处的问答可靠性，但会增加模型调用、耗时和 token 成本。

**控制变量**：相同 corpus、冻结 task IDs、LLM、温度、检索方法与 top-k；只对比是否存在证据缺口跟踪和动态查询/停止策略。比较同一批 case 的 claim-level 人工正确率、引用证据准确性、拒答的 precision/recall、平均及 P95 延迟、token 使用。**要单独记录“曾经对，改后错”的题目。**

**失败条件**：若增加 2 次工具调用后，人工答案质量没有可重复改进、反而造成无答案时幻觉或成本明显上升，则停止当前策略，回到固定检索/分级拒答。不能根据 dev set 错例反复改 holdout gold。

**预期科研贡献形式（目标，不是当前完成）**：系统架构图、开放标注说明、基线与消融结果、逐题错误分类、带 95% 区间的 paired delta、质量/成本曲线、可复现实验脚本、真实失败案例。

## 完整材料审查：课程 / 口试 / PPT / PDF / README

- **知识结构**：优先级 P0 Runtime + Search + Evaluation；P1 Skill/MCP、Recovery/Safety；P2 后训练。已修正幻灯片原先将 Search/Eval 标为 P2/P3 的矛盾。文档总时长建议以 65–85 小时/6–8 周为完整课程基准，两周为投递准备的短期支线，不能用“14 天研究完成”作承诺。
- **课件**：保留原 29 页主题，新增两页审计证据与困难负例；课程仍需用真实运行日志与学生回答来验证学习效果，不是看完 PPT 就获得实践能力。
- **题库**：原题库覆盖概念、预测、调试、反例和技术答辩；新增带版本控制/拒答失败的专题追问。要求学生在回答前先做预测，在运行后交报告，不提供可直接背诵的假证据。
- **PDF**：以 Markdown 源重建，抽查多页中文、表格与链接布局；源代码和排版版本必须与仓库同步，不能把旧 PDF 当新版本。
- **README**：首页应让 HR 首先看到可运行命令、实测结果与失效边界，而不是充满“完整工业方案”的营销用词。数值来源需标明 synthetic，遇到本轮故障必须写入日志。

## 最终再审核的门槛

1. 新数据有许可证、标注协议、真实 holdout 和盲验记录。
2. 真实模型任务结束状态明确，不把 `planning_failed` 或工具错误算成“拒答成功”。
3. 真实 MCP client/server + 中断/重启一体化测试有日志。
4. 明确的安全与数据许可；拒绝把真实企业私有内容自动发外部模型。
5. 研究报告的所有数字可追溯到 dataset hash / corpus hash / git SHA / 原始逐题 JSON。
6. 学生可不看模板独立实现关键逻辑，并回答为什么复杂方案有时更差。
